# ADR-012: ALU Output Interface and Flags

## Context
The Arithmetic Logic Unit (ALU) computes the primary result of an operation. We must define what additional status flags the ALU will output to the Control Unit and datapath.

## Decision
The ALU will output the main computation `Result`, along with four status flags:
* `Zero`
* `Carry`
* `Negative`
* `Overflow`

## Rationale
Adding these flags solves significant architectural problems while requiring minimal hardware overhead:
1. **Branch Decisions:** The `Zero` flag allows the Control Unit to immediately execute a `BEQ` instruction by checking the result of `Rs1 - Rs2` without requiring standalone comparison logic.
2. **Future Extensibility:** Standardizing `Negative` and `Overflow` flags allows us to implement instructions like `BLT` (Branch if Less Than) or `BGT` in future ISA revisions without redesigning the ALU interface.
3. **Verification:** Exposing flags dramatically simplifies functional verification. The testbench can assert expected flag states, making debugging easier.
4. **Physical Design Cost:** The area and timing penalties are virtually nonexistent. `Zero` requires a single comparator (`result == 0`), `Negative` is simply the MSB, and `Carry` is inherently generated by the adder.
